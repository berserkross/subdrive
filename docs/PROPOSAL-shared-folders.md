# 提案：共享目录（活动资料库）的权限模型

状态：**待拍板**。写下的是选项与后果，不是已定方案。拍板后本文件的结论并入 `DECISIONS.md`。

## 一、现状给这件事设了哪些硬约束

1. **没有任何文件/目录的数据库记录**。现有表只有 `users`、`invite_codes`、`sessions`、
   `usage_cache`、`audit_log`、`login_failures`（`app/main.py:78-137`）。目录树完全活在
   Seafile 里，`list_dir()` 返回什么就是什么。→ 想「给某个目录授权」，得先决定**权限挂在什么
   对象上**。
2. **没有组/团队概念**。只有「用户」和「管理员」两种身份。
3. **存储层只有一个 Seafile token**（`app/storage.py` 的 live 实现），所有用户共用它访问同一个
   仓库。Seafile 侧不认识我们的用户，所以**它自带的共享/群组功能在本架构里用不上**。
4. **归属门刚刚建好**：`_assert_full_path()` 要求路径落在 `/<当前用户>/` 下，管理员例外。
   任何共享目录都是「不在用户名下」的顶层面，**这道门必须被重新设计**，否则共享目录一上线
   就会被自己挡住。

## 二、四个方案

### 方案 A：共享目录 + 目录级 ACL（路径前缀授权）

新增两张表：

```sql
shared_dirs(id, slug, name, created_by, created_at)          -- 落盘在 /shared/<slug>/
shared_members(dir_id, user_id, role)                        -- role: viewer|uploader|admin
```

- 权限粒度是**目录**，不是文件——不需要给每个文件建行，与「没有文件表」的现状兼容。
- 归属门改成：路径在 `/<自己>/` 下 → 放行；在 `/shared/<slug>/` 下 → 查 `shared_members`。
- D26（同名按上传者分目录）自然落地：`/shared/<活动>/<用户名>/DSC_0001.JPG`。
- 列表接口要合并两处：自己的根 + 加入了的共享目录。

**代价**：改动最大（新表 + 新路由 + 归属门重写 + 前端多一个入口）；权限判断从「字符串前缀」
变成「查表」，是每请求一次 DB 查询（可缓存）。**收益**：摄影社团真正想要的多半是这个。

### 方案 B：直接用 Seafile 的共享能力

**排除**。理由见约束 3：所有用户共用一个 token，Seafile 认为只有一个人；要让它认人，得给每个
用户开 Seafile 账号并管密钥，等于把用户体系复制一份到外部系统。成本高于方案 A，收益为零。

### 方案 C：只做「上传收集箱」（只写不读）

一个目录一个入口，成员**只能往里投，看不到别人投了什么**；管理员（活动发起者）能看全部。

- 表可以更薄：甚至不需要 `shared_members` 的 `viewer` 角色，只留「谁能投」。
- 归属门只需放行 `/shared/<slug>/<自己>/` 的写操作，**读别人的目录一律拒**。
- 改动量约为方案 A 的 40%。
- **代价**：拍完、选片、互看都做不了。对「交片」够用，对「一起挑片」不够。

### 方案 D：一个公开目录，登录即可读写

`/shared/` 一个目录，不分活动、不分人。半天能上线。
**代价**：A 能删 B 的文件、谁都能看谁、无法追溯「这是谁传的」，D26 也就没有意义了。
只在「先能跑起来」时合理。

## 三、我的推荐：C 起步，留 A 的口子

先做 C，但**表结构按 A 设计**（`shared_dirs` + `shared_members` 都建，只是 C 阶段不使用
`viewer` 角色）。这样将来加「能看」时是加一行权限判断，不是重做数据模型。

如果一开始就知道要「一起挑片」，那别走 C——直接 A，省一次迁移。

## 四、必须由你拍板的五个问题（有依赖顺序）

1. **成员之间能不能看到对方交的片？** ← 根问题，决定 C 还是 A
2. 谁能删文件？（建议：只有上传者本人 + 目录 admin）
3. 上传的容量记在谁头上？（上传者 / 活动发起者 / 不记 —— 影响 `usage_cache` 与配额）
4. 一个活动一个目录，还是只有一个共享目录？（建议：一个活动一个）
5. 目录名是用户输入的中文活动名，还是 slug？（中文名在 URL 里要编码，建议 slug + 显示名分离）

## 五、如果选 C，改动清单（确认后照此执行）
