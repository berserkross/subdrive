# SubDrive 现状摘要

## 定位

摄影类社团内部网盘：多用户，文件本体存 Seafile（`app/storage.py` 有 stub/live 双实现），所有上传下载经后端流式转发，前端是原生 JS 单页。站点已上线，域名由前任维护者留下；现任维护者同时是网站管理员，但只有网站后台权限，没有服务器终端。

## 已知缺陷（只读审计确认，均未修）

1. **用户隔离现在是三道，但仍不防冒名**。①`app.paths.full_path()` 的前缀断言从 `assert`
   改成真 `raise`（`paths.py:87-88`）——原来的 `assert` 在 `python -O` 下会被整条剥离，线上
   若带 `-O` 启动就没有这道检查；②所有 full 路径必须经 `full_path()` 生成，`main.py:616`
   那处唯一的 `f"{full}/{name}"` 手拼已改掉；③存储层 `_assert_full_path()`（`storage.py:49-63`）
   额外校验首段必须是合法用户名形态。**但它仍然不知道「当前用户是谁」**，挡不住「拿着 alice
   的 token 访问 bob 的路径」——那需要存储层接收并比对 username，是一次改 11 个方法签名的
   重构。今天的防线是 ①②③ 的合力，不是任何单独一道。
2. **同名上传静默覆盖 —— 已定策略（D26），未实施**：`storage.py:168-171` 只挡「同名是目录」，
   文件走 `open(dst,"wb")` 截断，不留版本、不报错、前端只显示「完成 ✓」。用户已决定用
   「按上传者分目录 `活动名/用户名/`」解决，**但它依赖活动资料库（共享目录）先存在**；个人
   空间内同一个人覆盖自己的同名文件仍会静默发生（同一所有者的自身覆盖，暂按可接受处理）。
   落地时机：做共享目录时一并实现，届时 `usage_add` 的净增记账也要跟着改。
3. ~~**`.. `（尾随空格）绕过路径层**~~ **已修**：`paths.py:70-73` 拒绝一切尾随空格/点的路径段，
   `.. `／`...`／`a. ` 现在走 403，不再能绕过 `main.py:793` 的根目录删除保护。
4. **穿越电池已补齐**：HTTP 层 13 → 17 例（`test_smoke.py:143-146`），另加 12b 段直调存储层
   形状门 6 拒 3 放（`test_smoke.py:158-170`），不依赖路由即可回归。
