## 定位

摄影类社团内部网盘：多用户，文件本体存 Seafile（`app/storage.py` 有 stub/live 双实现），所有上传下载经后端流式转发，前端是原生 JS 单页。站点已上线，域名由前任维护者留下；现任维护者同时是网站管理员，但只有网站后台权限，没有服务器终端。

## 已知缺陷（审计确认；每条都标了当前状态）

1. **用户隔离已从「靠调用方自觉」变成强制门（管理员例外）**。四层：①`full_path()` 的前缀断言
   由 `assert` 改成真 `raise`——`assert` 在 `python -O` 下会被整条剥离，线上若带 `-O` 启动
   等于没有这道检查；②所有 full 路径必须经 `full_path()` 生成，`main.py:616` 那处唯一的手拼
   已改掉；③`require_user` 把「当前用户名 + 是否管理员」写进 `app/paths.py` 的 ContextVar；
   ④`_assert_full_path()` 据此拒绝落到他人前缀下的路径，stub 与 live 共用，live 的 `upload`
   因为自己拼 URL 而单独补了断言（其余方法都经 `_dir_url`/`_file_url`）。
   **残余风险**：（a）上下文靠 `require_user` 设置，将来若有路由绕过它直连存储层就没有这道门；
   （b）管理员被显式放行（校准、代管要跨用户），管理员 token 泄露仍等于全站文件可读——这是原有
   语义，没有变差，但也没有变好。
2. ~~**同名上传静默覆盖**~~ **已实施（D26/D27）**：写别人的共享目录时，落点被强制改成
   `<共享目录>/<自己的用户名>/`（`main.py` 上传路由），同名冲突因此变成「只可能覆盖自己」；
   `storage.upload()` 的 `wb` 截断保留，但路由先 `stat` 出旧大小、按 `stored - prior`

## 共享文件夹的实现边界（D27 定稿后，按默认规则推进，用户可随时推翻）

1. 授权名单可为空：等于「只有创建者能看」，但对象本身仍是共享文件夹，不降级为普通文件夹。
2. 授权成员不能再把文件夹转授给第三人（避免权限扩散，成员名单只有创建者能改）。
3. 目录 `rename` / `move` 必须与授权表在同一事务里同步路径前缀，否则权限静默失配。
4. 删除共享文件夹时，别的成员传进来的文件随之消失，配额回冲给**各自的上传者**（不还给创建者）。
5. 被移出名单的成员，其先前上传的文件仍留在目录里且仍占他的配额；他失去访问权，也失去自删权。
6. Seafile 侧不做真实 ACL：共享的可见性完全由后端归属门 + 数据库授权表决定。
