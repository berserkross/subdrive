# SubDrive 现状摘要

## 定位

摄影类社团内部网盘：多用户，文件本体存 Seafile（`app/storage.py` 有 stub/live 双实现），所有上传下载经后端流式转发，前端是原生 JS 单页。站点已上线，域名由前任维护者留下；现任维护者同时是网站管理员，但只有网站后台权限，没有服务器终端。

- 本地检查 126 项通过：原有 104 项 + 新增 22 项。后端功能用本地 stub，Seafile 适配用模拟响应。
- 已修：邀请码并发重复使用、管理员可被误禁用、负配额输入、预览内容类型、空文件 Range 下载边界。
- 存储层下载地址解析兼容 `302 + Location` 与 `200 + JSON`，含回归测试。
- 变更整理为 GitHub 草稿 PR（会话结束时仍在整理，未合并、未上线）。

## 已知缺陷（只读审计确认，均未修）

1. **用户隔离只有一道门**（部分缓解）。存储层已补 `_assert_full_path()`（`storage.py:49-61`，
   stub 与 live 共用）：挡绝对路径缺失、`..`、反斜杠、控制字符、尾随空格点。但它不知道当前
   用户是谁，**挡不住跨用户冒名**；真正的门仍是 `_user_full`（`main.py:587-590`）。
2. **同名上传静默覆盖**：`storage.py:168-171` 只挡「同名是目录」，文件走 `open(dst,"wb")` 截断，
   不留版本、不报错、前端只显示「完成 ✓」。这直接违背 `DECISIONS.md` D3 的「不能静默覆盖」，
   且 `usage_add` 按净增记账，覆盖后容量必然漂移。
3. ~~**`.. `（尾随空格）绕过路径层**~~ **已修**：`paths.py:70-73` 拒绝一切尾随空格/点的路径段，
   `.. `／`...`／`a. ` 现在走 403，不再能绕过 `main.py:793` 的根目录删除保护。
4. **穿越电池已补齐**：13 → 17 例，新增 `.. `／`...`／`a. `／NUL 四种形态（`test_smoke.py:143-146`）。
