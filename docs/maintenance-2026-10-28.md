# SubDrive 维护验收记录

日期：2026-10-28。基线：`1b7c5ee00f9c939c99deeca007acae656ebd9cde`。
本次为现有项目的维护迭代。代码在隔离环境验证；线上版本、真实存储链路和部署状态仍需实际验收。

## 本次完成

- 注册时在 SQLite 写事务中预占邀请码次数；建目录失败释放占用，异常类型正确导入。建目录期间用户保持 pending，避免半初始化账号登录。
- 禁止禁用所有者和当前账号，限制管理员互相禁用；拒绝负配额。
- 数据库上下文退出后显式关闭连接。
- HTML、SVG、XML 等以纯文本预览；文件响应增加 nosniff、no-store、no-referrer。
- 空文件的后缀 Range 返回 416；上游未知长度不伪造 Content-Length: 0。
- 存储读取使用有限空闲超时，下载建连失败释放客户端；启动 ping 的 false 结果也拒绝启动。
- 普通文件下载增加进度、取消、同文件重复点击保护、最多两个并行任务，保留后端错误和 HTTP 状态。退出登录时中止普通下载、清理加密目录状态和预览。

## 网站管理员可独立完成的验收

使用专门的两个普通测试账号 qa_a、qa_b；管理员只负责签发测试邀请码和调整测试账号配额。使用无敏感内容的照片、文本和短视频，放在 maintenance-test 目录。只对该目录和测试账号执行移动、删除、禁用等操作。

| 编号 | 操作 | 通过标准 |
|---|---|---|
| W01 | qa_a 上传小 JPG，刷新列表，预览，下载 | 文件名、大小正确；下载与原件 SHA-256 一致 |
| W02 | 中文、空格、#、& 文件名重复 W01 | 文件名不变且能正常访问 |
| W03 | 创建子目录、移动文件、改名后下载 | 新位置可访问，旧位置不误指向其他文件 |
| W04 | qa_b 登录并使用 qa_a 的测试文件相对路径请求 | 只解析 qa_b 自己的空间，不能读到 qa_a 的测试文件 |
| W05 | 新建一次性邀请码，完成一人注册后再次尝试 | 第二次被拒绝；不要在线发起并发压测 |
| W06 | 将 qa_b 设为小配额，再上传超限测试文件 | 明确提示超额，用量显示一致 |
| W07 | 下载时观察 Network 与任务栏，在测试中取消 | 明确显示连接、进度、取消或错误，不误报保存成功 |
| W08 | 对测试文件操作时在本机开发者工具切换 Offline，再恢复 | 前端提示失败并可重试；不关闭服务器或 Seafile |
| W09 | 使用手机或窄屏完成上传、预览和下载 | 操作入口可见，文字和按钮不重叠 |
| W10 | 管理员禁用 qa_b，再在 qa_b 会话刷新 | 已禁用账号被拒，管理员自己仍可使用 |

Windows 校验示例，在 PowerShell 分别运行并比较 Hash：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "C:\实际路径\原图.jpg"
Get-FileHash -Algorithm SHA256 -LiteralPath "C:\实际路径\下载图.jpg"
```

记录格式：时间、浏览器/设备、测试账号角色、操作步骤、预期、实际、HTTP 状态、脱敏截图、是否可重复。Network 选择 All 并保留日志；不要分享 Authorization、Cookie、完整 token 链接或未经脱敏的 HAR。

## 仅靠网站后台无法证实的事项

数据库和照片实际存储位置、备份能否恢复、容器镜像是否与 GitHub 一致、代理设置、主机资源和历史故障日志，需要服务器或运维系统权限。网页的 storage_mode 可说明应用报告的模式，不能证明全部部署配置正确。网页响应头也不能证明备份存在。

取得服务器权限后先做只读检查：项目提交号、容器状态、应用日志、入口代理配置、数据卷与备份计划。合并 PR 前确认是否配置自动部署；发布前保留可恢复备份和旧镜像，在测试环境验收后再发布。

## 已知限制与下一步

- 本次未部署线上，未进行真实 Seafile 集成验收、浏览器视觉验收和大文件负载测试。
- 浏览器仍需完整接收普通文件后生成 Blob 保存；进度和取消改善体验，但没有实现浏览器流式落盘或上传断点续传。加密文件下载仍使用原有流程。
- 邀请预占处理正常异常补偿；进程被强制终止可能留下 pending 用户与预占次数，需要后续增加恢复/对账任务。不要直接删除存储目录来修复这类状态。
- 上传配额预占、覆盖文件记账和校准并发尚未统一；首用户管理员初始化策略、URL 会话 token、会话清理和备份恢复仍需后续处理。
- 仓库依赖只声明下限，环境可漂移；本轮测试有上游 TestClient 弃用警告但无失败。应在部署环境验证后锁定依赖版本。
- 密码或提取码分享、活动共享空间、选片、回收站界面目前不是本次已交付功能。

## 受控分享的下一轮范围

建议先支持单文件只读分享：随机分享标识、单独提取码、默认 7 天有效期、随时撤销。提取码只存哈希；解锁有失败限流；访客使用短期且仅限该文件的凭证。每次取文件重新检查分享有效性及文件所有者状态。

分享必须绑定稳定文件标识或不可变版本，处理原文件删除、移动、覆盖的行为，避免旧链接意外分享新文件。预览与下载使用相同授权。不得把成员登录 token 放进分享链接，也不得向访客下发 Seafile 主账号凭证。提取码是访问控制，不等于端到端加密。

验收至少包括正确/错误提取码、过期、撤销、越权、所有者禁用、文件替换、限流、中文文件名与下载一致性。在这些结果出现之前，海报只能将该能力写为下一阶段计划。
