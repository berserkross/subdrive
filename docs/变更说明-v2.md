# SubDrive v2 更新包 — 变更说明

包基线：仓库 `main` 分支 `c393efc`（2026-10-28）。本地测试 263 项全部通过。
对照基线：线上当前运行的版本，即 v1 部署包对应的提交。

## 一、升级要点

- **依赖未变更**：`requirements.txt` 仍为 fastapi、uvicorn、python-multipart、httpx 四项。
- **数据库仅增加列，不改动既有数据**：`shared_folders` 新增 `max_bytes`、`max_members` 两列，
  启动时幂等执行（旧库自动补齐，重复启动不重复执行）。无删表、无列类型变更。
- **前端资源有变更**（`static/index.html`、`static/style.css`、`static/app.js`）：升级完成后
  需在浏览器端强制刷新一次（Ctrl/Cmd+Shift+R），避免加载缓存的旧脚本。
- 包内不含任何密钥，密钥仍由服务器上的环境变量文件提供。

## 二、批量操作（删除 / 移动 / 下载）

文件列表增加行首复选框与表头全选，勾选后底部浮出操作条：下载、移动、删除、取消。
操作范围限于当前目录，不跨目录；所选条目包含文件夹时「下载」不可用（浏览器对多文件只能逐个弹出保存框）。
后端未新增路由，复用 `/api/files/{delete,move}`。

## 三、同名文件覆盖确认

上传同名文件时，前端先查询目标文件是否存在，随后列出三个选项：**替换**、**两者都保留**、**跳过**。
选择「替换」时携带旧文件大小，由服务端复核；若期间文件已被他人改动，返回 `409 conflict` 且不写入。
选择「两者都保留」时，新文件以 `X (2).txt` 形式命名。

## 四、共享文件夹的容量与成员数上限

- `shared_folders` 新增 `max_bytes`、`max_members`；取值为 0 表示采用全局默认。
- 全局默认：容量 2 GiB、成员 20 人；成员数硬上限 200（`MAX_SHARED_MEMBERS`）。
- 超出容量：上传返回 `413 shared_full`；超出成员数：调整名单返回 `400 too_many_members`。
- 新增 `PATCH /api/shared/{id}`，用于修改上述两个上限。
- 共享目录的管辖权限放宽为「创建者或管理员」。

## 五、工具栏合并为单一新建入口

原为并排的多个按钮，现合并为：**＋ 新建 / ⬆ 上传（菜单：文件、文件夹）/ ⚡ 测速**。
新建弹窗一次性设定：类型（普通 / 加密）、可见性（私密 / 公开共享，公开共享仅管理员可见），
以及共享段的成员与上限。加密文件夹的密码逻辑未变更，详见 `CRYPTO.md`。

「⚡ 测速」沿用既有接口：`POST /api/speed/download`（默认 25 MB，上限 50 MiB）与
`POST /api/speed/upload`。同一时间只允许一路测速，第二个请求返回 `409 speedtest_busy`，
属限流设计而非故障。

## 六、共享弹窗的成员选择方式

成员改为勾选：提供「全部成员 / 仅指定成员」两个选项、搜索框与复选列表，成员较多时无需手工输入用户名。
创建者本人不出现在可勾选列表中（其为所有者，无需向自己授权）。
若选择「仅指定成员」而未勾选任何人，前端将阻止提交，不发出空名单。
容量以「数字 + GB/MB」单位输入，成员数以「数字 + 上下箭头」输入，留空表示采用默认值。

配套新增 `GET /api/users/directory`（仅管理员），为选择器提供成员数据。

## 七、昵称

新增 `POST /api/me/nickname`：在页面顶部点击本人头像或用户名即可修改，最长 40 字，清空后回落到登录名。
**登录名（username）不可修改**：它出现在物理存储路径与共享授权前缀中，改名等同于同时迁移目录与授权记录。

## 八、公共区域

页面上方新增「我的网盘 / 公共区域」两个视图。

公共区域为只读索引：列出当前账号有权访问的共享文件夹（名称、创建者、成员上限、已用空间与容量上限）。
进入条目后即为该共享目录本身，可正常读写；上传仍落在 `<共享目录>/<本人用户名>/`。
面包屑首格为「公共区域」，点击可返回索引。同一目录存在两个入口，从何处进入即返回何处。

## 九、两处缺陷修复

- **空名单的语义**：此前「零条授权记录」被解释为「无人可进入」。创建者建立共享时往往尚无第二个账号，
  导致此后注册的账号始终无法获得授权。现改为读取时解释：无名单表示全体成员，有名单则按名单执行，
  名单收窄立即生效。
- **进入共享目录的落点**：此前被授权者进入后列出的是对方根目录，并随即被 403 拦截。现改为落在共享目录本身。
  两处缺陷均由浏览器端到端测试发现，仅靠后端单元测试无法暴露。

## 十、数据库变更

以下语句在启动时自动执行，无需手工操作：

```sql
ALTER TABLE shared_folders ADD COLUMN max_bytes   INTEGER NOT NULL DEFAULT 0;
ALTER TABLE shared_folders ADD COLUMN max_members INTEGER NOT NULL DEFAULT 0;
```

其余表（users、invite_codes、sessions、usage_cache、audit_log、login_failures、shared_folders、
shared_grants）均以 `CREATE TABLE IF NOT EXISTS` 建立。旧库升级不需要手工执行 SQL。

## 十二、已知边界与后续事项

- live 模式（对接真实 Seafile）仍依赖服务器侧的令牌。本地端到端测试运行于 stub 存储，
  浏览器、HTTP 与后端均为真实链路，仅文件本体落在本地磁盘。
- 公共区域未实现「虚拟根 + 完整目录树」，无法在各共享文件夹之间直接跳转。
- 批量下载为逐个弹出保存框，尚未实现后端打包。
