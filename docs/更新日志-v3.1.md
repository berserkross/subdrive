# SubDrive v3.1 更新日志（2026-11-12）

一句话：**三语、双主题、上传不再冻站。**

这一版没有加新功能入口，改的三件事都在「用起来顺不顺手」这一层：界面能说三种话、
白天黑夜都能看清、传大文件的时候别人不再被卡住。

---

## 1. 三语支持（D41）

- 新增**繁体中文**字典：285 个键位，与简体、英文逐键等长（缺键会在 e2e 里立刻暴露）。
- 顶栏语言胶囊从「中 ⇄ EN」改成三态循环：**中 → 繁 → EN → 中**，按钮上显示的是「当前语言」而不是「下一个」。
- `<html lang>` 跟着切换：`zh-CN` / `zh-Hant` / `en`（读屏软件与浏览器的断行规则都靠它）。
- 错误码文案补齐三语：`ERROR_I18N`（英文 41 条）、`ERROR_ZH`（中文 41 条，新增）、`ERROR_HANT`（由中文转写）。
  后端返回的 `error` code 命中就显示本语言文案，没命中才显示服务端原文——翻译只发生在表现层，后端没动。
- 选择存在 `localStorage.subdrive_lang`；旧值 `zh`/`en` 继续有效，非法值回落简体。
- 切语言时会把主题按钮的 `title`/`aria-label` 一起刷新（这一条是 e2e 抓出来的：换语言后按钮上还挂着中文提示）。

**加第四种语言要动的地方**（三处，没有第四处）：
1. `static/app.js` 里复制一份字典块（键必须与 zh 等长）；
2. `LANG_ORDER` / `LANG_LABEL` / `HTML_LANG` 各加一项；
3. 如果是 RTL 语言，再给 `body` 加一条 `dir` 规则。

## 2. 浅色 / 深色 / 主题色（D42）

**两层含义分清楚**：`data-theme` 决定明暗，`data-accent` 决定主色。两个属性都挂在 `<html>` 上，
组件样式只认 token（`--bg`/`--surface`/`--text`/`--accent`…），不认识「浅色」「深色」这两个词。

- **浅色**＝历史默认那套（`--bg:#eceef3`、白卡片、`#5b5bd6→#8b5cf6` 渐变主色），也就是易拉宝
  `_poster/images` 里截出来的那一版配色，没有改动。
- **深色**＝旧版深色方案（`#0d0f13` / `#15181e` / `#eef1f4`），语义色（危险/成功/警告）一起换。
- **第三种状态：跟随系统**——不写 `data-theme`，由 `@media (prefers-color-scheme: dark)` 接管。
- 顶栏与登录页各有一个主题按钮，点开是一个面板：**明暗三选一**（浅色 / 深色 / 跟随系统）+ **主色色板**
  （默认紫、ocean、forest、sunset，再加一个彩虹圆 = 自选颜色）。选择存 `subdrive_theme` / `subdrive_accent`，刷新保持。
  登录页也放了一个，深色用户不会一进来被闪一下。
- 自选颜色走 `<input type="color">`，存成 `#rrggbb`：`applyTheme()` 用 inline 变量覆盖 `--accent`，
  并用 `color-mix` 派生 `--accent-2`/`--accent-grad`/`--accent-soft`——**加一个预设只改 CSS，用户自选一个颜色不写 CSS**。
- `color-scheme` 跟着主题走，原生控件（复选框、下拉、滚动条）不再在深色里发光。
- **两个可扩展入口**（主色已经接进面板；贴图仍是预留）：
  - 主色：`window.SubDriveTheme.accent("ocean")`，或直接传 `#0f6fbf`；
    已内置 `ocean` / `forest` / `sunset` 三组预设（每组都配了深色下的 soft 值）。
  - 贴图：`--bg-image` 变量已经挂在 `body` 的 `background-image` 上，默认 `none`；
    将来把某张图或渐变塞进 `[data-theme="dark"]` 即可，无需改组件。

## 2.5 顶栏：语言下拉 + 固定槽位 + SVG 图标（D44）

- 语言从「点一下循环」改成**下拉直接选**：简体 / 繁體 / English（各写自己的语言名，不翻译）。
- 右上角六个控件全部给定宽度，取三语里最长的那条文案；实测 zh / hant / en 三种语言下每个控件的
  x 坐标完全一致（漂移 0px），切语言不再左右乱跳。
- 主题按钮与面板里的三档图标从字形（☀ / ☾ / ⚙）换成**内联 SVG**：Windows 缺字时字形会整格空白，
  用户机器上就是这样看不到的；SVG 不依赖字体，任何机器都长一样。
- 深色辅助文字提亮（`--text-2:#a6afbd`、`--text-3:#7b8492`），成员上限/容量/说明在卡片底上能读清；
  用户胶囊 206→186px；色板选中环 2px→1.5px（这三条来自 Codex 的截图评审）。
- 语言名不翻译带来的测试调整：e2e 的「EN 零 CJK」扫描把 `简体`/`繁體` 两个词白名单掉。

## 3. 上传卡顿：先证明，再修（D43）

### 3.1 现象
传大文件时，同一站点上的其它操作（刷新列表、翻目录、改配额）会突然停住一两秒；
进度条偶尔一顿一顿。

### 3.2 怎么量的（可复跑）
脚本 `_bench_upload.py`：起一个 stub 实例，用 `curl -F` 上传 200 MiB，
**同时**每 100 ms 打一次 `GET /api/files/list?path=/` 记延迟。

| 指标 | 改前 | 改后 |
|---|---|---|
| 200 MiB 上传总耗时 | 7.40 s | **4.43 s** |
| 吞吐 | 27 MB/s | **45 MB/s（+67%）** |
| 列表延迟 p50 | 39.6 ms | 36.6 ms |
| 列表延迟 p95 | 121.8 ms | **72.7 ms** |
| 列表延迟 max | **2181.9 ms** | **94.6 ms** |
| 超过 1 s 的样本 | 1 | **0** |

### 3.3 结论：两处，各占一半
1. **后端真的卡**。`files_upload` 先把请求体分块写进临时文件（这一步是异步的，没问题），
   收完以后调用 `storage.upload()`——stub 实现是**同步的整文件拷贝**。uvicorn 单 worker，
   这一秒级的拷贝就跑在事件循环上，期间所有请求排队。max 2181 ms 就是它。
2. **前端也在抖**。`xhr.upload` 的 `progress` 回调每个事件都写一次 `style.width` 和 `textContent`，
   Chrome 每秒能触发几十次，等于在主线程上反复触发样式计算与布局。

### 3.4 修法
后端：
- `storage.accept_temp()` 新入口：默认等价于 `upload()`（live/Seafile 行为完全不变）；
  stub 实现发现临时文件与目标目录**同卷**时直接 `os.replace`——O(1) 换目录项，不读不写。
- 上传临时文件改放 `DATA_DIR/.upload-tmp`，保证同卷；跨卷（有人把 DATA_DIR 指到别的盘）自动退回拷贝。
- 所有阻塞存储调用（`stat` / `mkdir` / `accept_temp`）都套 `run_in_threadpool`，事件循环不再被按住。
- 新增 `SUBDRIVE_UPLOAD_TIMING=1`：每个文件打印 `recv=`（收字节）/`store=`（落盘）/`total=`，
  下次再怀疑卡顿，先看这三个数，不用猜。

前端：
- 进度写入改成 `requestAnimationFrame` 合并：事件只更新 `pendingPct`，一帧最多写一次 DOM；
  百分比没变就直接丢；完成时先 `cancelAnimationFrame` 再一次性置 100%，不会出现「99% 僵住」。

### 3.5 队列：从「一个个传」改成「按在飞字节并行」

原来的队列是严格串行的：一个文件传完才发下一个。对本地网络几乎看不出来，
但在真实链路上，每传一个小文件就要多等一个 RTT，几十个文件就是几十个 RTT 的纯等待。

现在是**双阈值**调度：同时最多 3 个请求，且在飞字节不超过 64 MiB（大文件自己占满带宽，
小文件可以并行）；第一个请求永远放行，避免超大文件因超预算而永远排在队首。
同名冲突弹窗做了串行化——同一时刻只允许一个弹窗，后面排队的等前面选完。
并发上限可以通过 `window.SubDriveUploadTuning = { maxConcurrent, maxInflightBytes }` 覆盖，
将来做设置项时直接接这里。

实测（Chrome DevTools 加 40 ms 人为延迟，30 个 300 KB 文件）：

| 配置 | 总耗时 | 说明 |
|---|---|---|
| 串行（maxConcurrent=1） | 4.08 s | 每个文件一次 RTT |
| 并发（maxConcurrent=3） | **1.58 s** | **约 2.6 倍** |

本地无延迟时差异很小（1.8 s → 1.6 s），因为瓶颈不在 RTT；这条改动是给真实网络用的。

## 5. 升级与兼容

- 无需数据库迁移；首次启动会自动建 `DATA_DIR/.upload-tmp`。
- 新增环境变量：`UPLOAD_TMP_DIR`（临时目录，默认 `DATA_DIR/.upload-tmp`）、
  `SUBDRIVE_UPLOAD_TIMING=1`（上传分段计时日志，默认关）。
- `SEAFILE_MODE=live` 的路径没有改逻辑：`accept_temp` 默认就是原来的 `upload`。
- 旧浏览器（不支持 `color-mix`/`data-*` 选择器）会退化成浅色主题，功能不受影响。
