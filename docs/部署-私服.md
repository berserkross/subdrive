# 私服部署（自己的服务器 + 域名 + HTTPS）

> 目标：把 SubDrive 部署到一台公网/内网服务器，团队成员用 `https://drive.example.com` 访问。
> 面向：有一台 Linux 服务器（推荐 Ubuntu 22.04/24.04）和域名的人。只想本机跑请走 [部署-本地.md](部署-本地.md)。

## 0. 架构与前置

```
浏览器 ──HTTPS──> Caddy/Nginx（443，反代） ──HTTP──> SubDrive 容器（127.0.0.1:8001 → 容器 8000）
                                                        │
                                                        └── /data（SQLite + 文件；volume）
```

- 服务器：1 vCPU / 1 GB 内存起步即可（多人并发上传建议 2 GB）
- 域名一条 A 记录指向服务器
- 放行 80/443；**8001 不要对公网开放**
- 可选：真实 Seafile（`SEAFILE_MODE=live`），否则用内置 `stub` 存储

## 1. 装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"   # 重新登录后生效
docker compose version            # 需要 v2
```

## 2. 取代码

```bash
sudo mkdir -p /srv && sudo chown "$USER" /srv
git clone https://github.com/berserkross/subdrive.git /srv/subdrive
cd /srv/subdrive
```

## 3. 写环境文件（不要提交进 git）

```bash
umask 077
cat > .env <<'EOF'
SEAFILE_MODE=stub
SUBDRIVE_ADMIN_USERNAME=admin
SUBDRIVE_ADMIN_PASSWORD=换成一个强密码
DEFAULT_QUOTA_BYTES=21474836480
MAX_FILE_BYTES=2147483648
EOF
chmod 600 .env
```

要接真实 Seafile，把 `SEAFILE_MODE` 改 `live` 并补：

```bash
SEAFILE_BASE_URL=https://seafile.example.com
SEAFILE_API_TOKEN=...        # Seafile 里生成的 API Token，只放这里
SEAFILE_REPO_ID=...          # 专用库 subdrive 的 repo_id
SEAFILE_REPO_NAME=subdrive
```

> `/data` 里会存 SQLite 与本地文件。用 `live` 时，文件名/目录仍由 SubDrive 管，内容落 Seafile。

## 4. 让 compose 读取 .env 并启动

`docker-compose.yml` 里的环境变量默认写死为 `stub`。把 `environment:` 段替换成：

```yaml
    env_file:
      - .env
```

然后：

```bash
docker compose up -d --build
docker compose ps           # 等状态变成 healthy/running
curl -fsS http://127.0.0.1:8001/api/health
```

## 5. 反代 + HTTPS（Caddy，最省事）

```bash
sudo apt install -y caddy
sudo tee /etc/caddy/Caddyfile >/dev/null <<'EOF'
drive.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8001
}
EOF
sudo systemctl reload caddy
```

Caddy 会自动申请并续期证书。改用 Nginx 时，关键三行是：

```nginx
client_max_body_size 2g;                 # 必须 ≥ MAX_FILE_BYTES
proxy_request_buffering off;             # 大文件直传，别先落盘
proxy_read_timeout 3600s;
```

## 6. 首次登录与初始化

1. 打开 `https://drive.example.com`
2. 用 `.env` 里的管理员账号登录（或第一个注册的账号自动成为管理员）
3. 管理后台 → 生成邀请码发给成员
4. 设置 → 外观，选主题；组织主题可在管理后台统一设置

**务必**：登录后立刻改掉初始化密码；邀请码设置过期时间。

## 7. 备份与升级

**备份**（数据全在 volume 里）：

```bash
docker run --rm -v subdrive_subdrive-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/subdrive-$(date +%F).tgz -C /data .
```

**升级**：

```bash
cd /srv/subdrive
git pull --ff-only
docker compose up -d --build
```

升级前先备份；`/data` 不动，升级不会丢数据。

## 8. 上线检查清单

- [ ] `8001` 只监听 `127.0.0.1`（compose 已如此），公网只开 80/443
- [ ] HTTPS 证书有效，HTTP 自动跳转
- [ ] 反代 `client_max_body_size` ≥ `MAX_FILE_BYTES`
- [ ] 管理员密码非默认值，邀请码有有效期
- [ ] 备份任务已跑通一次（并试着解包看一眼）
- [ ] `SEAFILE_MODE=live` 时，Seafile Token 只存在服务器 `.env`（600），不进聊天、不进 git

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 502 Bad Gateway | 容器没起来或端口不对：`docker compose logs --tail=100 subdrive` |
| 上传 413 | 反代体积限制：Nginx 的 `client_max_body_size` / Caddy 默认无限制但被前置代理挡了 |
| 上传中断 | `proxy_request_buffering off` 未开，或 `proxy_read_timeout` 太短 |
| 数据"消失" | 换了 volume 名或没挂载 `/data`：`docker inspect subdrive | grep -A3 Mounts` |
| 登录被锁 | 默认 5 次失败锁 10 分钟；调整 `LOGIN_MAX_FAILS` / `LOGIN_LOCK_MINUTES` |
