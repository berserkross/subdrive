# SubDrive 网页端更新包 — 部署说明

包版本：v2（仓库 `main` 分支 `c393efc`，2026-10-28）
适用对象：负责服务器部署与运维的人员
文档性质：本包配套的操作说明，按顺序执行即可完成升级

本包**不含任何密钥**。密钥仍由服务器上权限为 600 的环境变量文件提供，升级过程中无需改动。

## 一、包内容

后端为 FastAPI，前端为原生 JavaScript，二者构成一套可直接运行的完整程序，目录结构与此前部署的版本一致。

```
Dockerfile            容器内监听 8000
docker-compose.yml    映射 127.0.0.1:8001:8000，由 Caddy 反向代理提供 HTTPS
requirements.txt      依赖清单（本次未新增依赖）
app/                  后端：main.py（路由、审计、配额）、storage.py（stub/live 两种存储）、paths.py（路径安全）
static/               前端：index.html、style.css、app.js、vault.js、uploadplan.js 及两个图标资源
.env.example          环境变量样例，值均为空，仅供对照字段
VERSION.txt           版本与基线信息
变更说明.md            本次更新的功能与接口变更
部署说明.md            本文档
```

另附 `README.md`、`CRYPTO.md`、`LICENSE`，供查阅。

## 二、升级前置：备份数据

数据位于命名卷 `subdrive-data`，其中包含 `subdrive.db` 与 stub 模式下的文件本体。

```bash
docker run --rm -v subdrive-data:/data -v /root/backup:/backup alpine \
  tar czf /backup/subdrive-data-$(date +%Y%m%d).tgz -C /data .
```

新版本首次启动时会以 `CREATE TABLE IF NOT EXISTS` 建出缺失的表，并对 `shared_folders` 幂等追加两个列，
不删除表、不修改既有列类型、不迁移既有数据。备份仍应作为升级前的固定步骤执行。

## 三、升级步骤

将包内文件解压并覆盖至原项目目录（`app/`、`static/`、`Dockerfile`、`docker-compose.yml`、
`requirements.txt`），随后执行：

```bash
cd <原项目目录>
docker compose build
docker compose up -d
docker compose logs --tail=50 subdrive
```

环境变量无需修改，继续使用服务器上现有的配置（`SEAFILE_MODE`、`SEAFILE_BASE_URL`、
`SEAFILE_API_TOKEN`、`SEAFILE_REPO_ID`、`SUBDRIVE_ADMIN_*` 等）。

## 四、存储模式：本次升级唯一的风险点

仓库内 `docker-compose.yml` 的 `SEAFILE_MODE` 固定写作 `"stub"`，属入库时的占位值。

若线上通过服务器环境变量或 compose override 将其设置为 `live`，**覆盖文件后必须确认该值仍为 `live`**。
一旦回落为 `stub`，服务外观与功能均正常，但文件只会写入容器本地卷，不会进入 Seafile，
且该问题在界面上不产生任何报错。

升级完成后建议执行一次 `docker compose config | grep -i seafile_mode`，或查看容器内环境变量，
确认实际生效值符合线上既定配置。

## 五、反向代理的两个参数

1. **上传体积上限**：单文件上限为 2GB（`MAX_FILE_BYTES`）。Caddy 默认配置可能在请求到达后端之前
   就将其截断，表现为大文件中途返回 502 或 413。建议在 Caddyfile 中显式放开：
   新语法 `request_body { max_size 2GB }`，旧语法 `limits { ... }`。
2. **超时**：大文件上传与测速会持续数十秒，`reverse_proxy` 的默认值通常足够。若前置还有 Cloudflare，
   需注意其 Free 套餐的上传体积与空闲超时限制；该限制属于 Cloudflare 一侧，与本程序无关。

## 六、升级后验收

按顺序逐条确认：

1. 访问站点可正常显示登录页（`GET /` 返回 200）。
2. 未登录状态刷新页面不会输出任何用户数据（`GET /api/auth/me` 返回 401）。
3. 使用既有账号登录，文件列表与升级前一致。
4. 上传一个小文件并下载，字节数一致；存储空间进度条数值随之变化。
5. 点击「＋ 新建」，弹窗内应出现类型（普通/加密）、可见性（私密/公开共享）与共享段（成员、容量、成员数）。
6. 以管理员身份创建一次公开共享：成员选择器应可用（全部成员/仅指定成员、搜索、复选），
   创建成功后「公共区域」内出现该条记录。
7. 点击「⚡ 测速」，能返回速率数值，说明流式转发链路正常。
8. 文件列表可勾选多个条目，底部出现批量操作条（下载、移动、删除、取消）。

任一条不符合预期时，`docker compose logs --tail=200 subdrive` 中会有对应的堆栈信息。

## 七、回滚

旧镜像仍在时：

```bash
docker compose down
docker tag subdrive:latest subdrive:before-$(date +%Y%m%d)
# 恢复旧镜像或旧代码目录
docker compose up -d
```

数据卷 `subdrive-data` 无需处理，本次不包含破坏性 schema 变更；如确需恢复，使用第二节的备份。

## 八、相对旧版本的行为变化

1. **同名文件上传不再静默覆盖**：前端会先探测目标文件，弹出「替换 / 两者都保留 / 跳过」三个选项；
   选择「替换」时携带旧文件大小，服务端复核不一致则返回 `409 conflict` 且不落盘。
2. **配额记账改为按增量**：覆盖写不再重复累加配额。
3. **共享文件夹**：创建者可为共享目录设定容量上限与成员数上限（默认 2 GiB / 20 人，成员数硬顶 200）；
   成员在共享目录内的上传落在 `<共享目录>/<成员用户名>/` 下，配额计入上传者本人；
   共享目录及其上级目录禁止改名、移动、删除，以免授权记录与实际路径失配。
4. **工具栏合并为一个「＋ 新建」入口**：类型、可见性、共享设置在同一弹窗内完成；上传改为下拉菜单
   （文件 / 文件夹）。
5. **昵称可修改**：`POST /api/me/nickname`，最长 40 字，清空后回落到登录名；登录名本身不可修改。
6. **公共区域**：页面上方提供「我的网盘 / 公共区域」两个视图，后者以只读索引列出当前账号有权访问的
   共享目录，进入后可正常读写。
7. **批量操作**：删除、移动、下载支持多选，作用范围限于当前目录。

## 九、常见错误码

| 状态码 / 错误 | 含义 | 处理方式 |
|---|---|---|
| `409 speedtest_busy` | 同一时间仅允许一次测速 | 稍后重试，属限流设计 |
| `413 shared_full` | 共享目录超出其容量上限 | 由创建者或管理员调整上限 |
| `400 too_many_members` | 成员数超出上限 | 调整名单或上限 |
| `409 conflict` | 覆盖写时目标文件已被他人改动 | 重新确认后再上传 |
| `502` / `413`（大文件中途失败） | 反向代理层的体积限制 | 见第五节 |
